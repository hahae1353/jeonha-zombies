**장르:** 한국풍 궁궐 좀비 아포칼립스 · 가챠 기반 실시간 생존 액션 로그라이크

**문서 상태:** 게임 기획 초안 v0.1 — 구현 전 수치·명칭·세부 규칙 변경 가능

## 1. 게임 개요

### 1.1. 한 줄 소개

좀비가 창궐한 궁궐에서 무작위로 얻은 무기와 궁중 물품을 활용해 살아남고, 무기를 전설 단계까지 진화시켜 반란을 일으킨 왕의 동생을 처치하는 생존 액션 게임.

### 1.2. 기본 규칙

- 플레이어는 시작 시 캐릭터를 뽑고, **무기 1개만 장착**한다.
- `WASD`로 직접 이동하고 무기는 일정 주기로 **자동 공격**한다.
- 몬스터 처치 시 떨어지는 **에너지 구슬을 수집**해 가챠 게이지를 채운다.
- 게이지가 가득 차면 전투가 일시정지되고 **가챠 보상**을 획득한다.
- 보상은 체력 회복, 무기, 패시브 등으로 구성한다.
- **같은 무기**를 다시 뽑으면 현재 무기를 강화한다.
- **다른 무기**를 뽑으면 현재 무기를 유지하거나 새 무기로 교체한다.
- 특정 강화 조건을 달성하면 무기가 **새 이름과 강화된 성능을 지닌 전설 무기**로 진화한다.
- 가챠 보상이 마음에 들지 않으면 제한된 횟수만큼 **리롤**할 수 있지만, 리롤할수록 적의 위험도가 증가한다.
- 시간이 흐르면 더 강한 좀비가 등장하며, 마지막에는 **좀비가 된 왕의 동생**과 싸운다.

## 2. 기획 의도와 핵심 재미

### 2.1. 기획 의도

실시간 생존 액션의 직관적인 조작에 가챠의 기대감과 위험 부담을 결합한다. 플레이어는 무작위 보상을 통제할 수 없지만, 보상을 **유지할지·교체할지·리롤할지** 선택할 수 있다. 따라서 운이 빌드의 출발점을 만들고, 이동·회피·보상 선택이 생존 결과를 결정하도록 한다.

### 2.2. 핵심 재미

| 핵심 요소 | 플레이어 경험 |
| --- | --- |
| **가챠의 기대감** | 다음에 어떤 무기와 패시브가 나올지 기대한다. |
| **위험을 감수하는 리롤** | 더 좋은 보상을 노리되, 강해질 적을 고려한다. |
| **단일 무기 집중 육성** | 무기 중복 획득으로 강화하고 전설 진화를 노린다. |
| **즉각적인 생존 액션** | 적을 피하고 구슬을 회수하며 게이지 충전 속도를 높인다. |
| **사극 블랙코미디** | 진지한 궁궐 재난 속 엉뚱한 아이템 설명과 캐릭터 반응을 즐긴다. |

### 2.3. 차별화 지점

본 프로젝트는 장르 자체의 독창성을 주장하지 않는다. **궁궐 좀비 아포칼립스라는 배경**, **리롤이 적의 위험도를 높이는 선택**, **무기 1개만 장착하는 교체·중복 강화·전설 진화**, **사극식 유머**를 조합해 고유한 플레이 경험을 만드는 것이 목표다.

## 3. 세계관과 스토리

### 3.1. 배경

조선시대를 모티브로 한 가상의 왕국. 왕의 동생은 자신이 왕위에 올라야 한다고 믿고 반란을 계획한다. 그 과정에서 좀비 감염 사태가 발생하고, 감염은 궁궐에서 시작해 나라 전체로 퍼진다.

> **설정 확정 범위:** 왕의 동생이 왕위를 노리며 반란을 꿈꿨고, 그 과정에서 좀비 바이러스가 창궐했다. 바이러스의 정확한 기원·유포 방식·동생의 의도적 살포 여부는 아직 확정하지 않는다.

궁궐은 무너진 담장, 어지러운 내전, 피 묻은 돌바닥, 쓰러진 깃발, 훼손된 궁중 물품이 남은 아포칼립스 공간이다. 감염된 백성부터 궁녀·내시·호위무사까지, 과거의 신분과 역할을 반영한 좀비들이 플레이어를 습격한다.

### 3.2. 목표와 결말

플레이어는 좀비 무리 속에서 살아남아 왕의 동생과 맞서 싸운다. 최종 보스를 처치하면 해당 플레이가 클리어된다. 엔딩에서는 선택한 캐릭터에 따라 짧은 대사가 달라진다.

### 3.3. 분위기

- **비주얼:** 한국풍 궁궐 + 좀비 아포칼립스, 어둡고 긴장감 있는 배경.
- **게임플레이:** 빠른 이동과 회피, 반복 가챠를 통한 가벼운 몰입.
- **유머:** 아이템 이름·설명·일부 적 대사·엔딩 문구에만 절제된 사극식 개그를 사용.
- **표현 방향:** 세계 자체는 진지하게 망해가지만, 살아남는 사람들의 반응은 때때로 엉뚱하다.

## 4. 게임 진행 구조

```text
타이틀 화면
    ↓
캐릭터 가챠 / 초기 무기 지급
    ↓
궁궐 생존 전투 시작
    ↓
WASD 이동 + 무기 자동 공격
    ↓
좀비 처치 → 에너지 구슬 드롭 → 수집
    ↓
가챠 게이지 최대치 도달
    ↓
전투 일시정지 → 보상 뽑기
    ├─ 보상 확정
    └─ 리롤 (위험도 증가) → 보상 재추첨
    ↓
무기 강화·교체 / 패시브 적용 / 체력 회복
    ↓
전투 재개 → 다음 게이지 요구량 증가
    ↓
시간 경과에 따라 적 종류·위협 증가
    ↓
왕의 동생(최종 보스) 등장
    ├─ 처치 성공 → 클리어
    └─ 플레이어 HP 0 → 게임오버
```

**핵심 원칙:** 가챠는 플레이를 멈추는 보상 구간이며, 전투 중에는 이동과 회피에 집중한다.

## 5. 조작 및 실시간 전투

### 5.1. 조작

| 입력 | 기능 |
| --- | --- |
| `W / A / S / D` | 상 / 좌 / 하 / 우 이동 |
| 마우스 클릭 | 가챠 보상 확정·리롤·무기 교체 선택 |
| `ESC` *(예정)* | 일시정지 메뉴 |
| 공격 입력 | 없음 — 장착 무기가 자동 공격 |

### 5.2. 플레이어 기본 상태

- HP, 최대 HP, 방어력, 이동속도, 피격 후 무적 시간 등으로 구성한다.
- HP가 0이 되면 게임오버된다.
- 피격 시 넉백 또는 짧은 무적 시간을 적용해 연속 접촉 피해를 방지한다. *(세부값 미확정)*
- 무기 공격 주기는 쿨타임으로 관리한다.

### 5.3. 전투 판정

1. 몬스터가 플레이어 위치를 기준으로 이동한다.
2. 장착 무기는 설정된 쿨타임마다 자동 공격한다.
3. 공격과 몬스터가 충돌하면 피해를 적용한다.
4. 몬스터 HP가 0 이하가 되면 제거하고 에너지 구슬을 생성한다.
5. 플레이어가 구슬의 획득 범위에 들어오면 구슬을 회수한다.
6. 몬스터와 플레이어가 충돌하면 회피·방어·무적 상태를 확인한 후 피해를 적용한다.

## 6. 플레이어 캐릭터

### 6.1. 설계 원칙

모든 캐릭터는 **동일한 이동·공격·피격 코드를 공유**한다. 캐릭터별 차이는 기본 스테이터스, 스프라이트, 짧은 대사에 집중한다. 따라서 캐릭터 수가 늘어나더라도 전용 전투 로직은 추가하지 않는 것을 원칙으로 한다.

### 6.2. 캐릭터 목록

| 캐릭터 | 역할 이미지 | 능력치 방향 | 대사 예시 |
| --- | --- | --- | --- |
| **왕** | 왕국의 통치자 | 균형형 | “역모는 실패했다. 그런데 이제 누가 나라를 다스리지?” |
| **호위무사** | 왕실 경호 인물 | 높은 HP·방어, 느린 이동 | “전하, 역적을 처단하였사옵니다!” |
| **내시** | 궁중 시종 | 빠른 이동, 낮은 방어 | “전하아아! 살아남았사옵니다아!” |
| **중전** | 왕비 | 균형·생존형 | “이제 궁궐 청소는 누가 한단 말이냐.” |
| **궁녀** | 궁중 여성 시종 | 빠른 이동, 낮은 HP | “드디어 퇴궐이다.” |
| **의적** | 궁궐에 휘말린 의적 | 기동형 | “왕실의 보물은… 이제 주인이 없겠군.” |
| **의관** | 궁중 의료 담당자 | 생존형 | “이 병은 의서에도 없었는데…” |
| **백성** | 평범한 생존자 | 기본형 | “나는 대체 왜 여기까지 온 거지?” |

> **용어 참고:** 궁중 의료 담당 남성 캐릭터는 ‘의관’, 여성 의료인 캐릭터는 ‘의녀’라는 명칭을 사용할 수 있다. 위 표의 능력치 방향과 대사는 기획안이며 실제 밸런스 수치는 미확정이다.

### 6.3. 제작 전략

- `Player` 클래스는 공통으로 사용하고 캐릭터별 스탯을 데이터로 분리한다.
- 모든 캐릭터에 동일한 크기와 프레임 규격을 적용한다.
- **8종은 최종 후보 목록**이며, 초기에는 1~2종의 스프라이트로 플레이를 완성한 뒤 추가한다.
- 캐릭터가 8종이 되어도 코드보다 **스프라이트·애니메이션 제작량**이 주요 부담이 될 수 있다.

## 7. 무기·교체·강화·전설 진화

### 7.1. 공통 규칙

- **동시에 장착 가능한 무기는 1개.**
- 같은 무기를 뽑으면 해당 무기 레벨이 상승한다.
- 다른 무기를 뽑으면 **기존 무기 유지 / 새 무기로 교체** 중 선택한다.
- 무기 교체 시 새 무기는 기본 레벨부터 시작한다는 안을 우선 검토한다. *(확정 전)*
- 특정 레벨 또는 중복 획득 조건을 만족하면 기존 무기가 **전설 단계로 진화**한다.
- 전설 진화는 별도의 무기 종류를 새로 뽑는 것이 아니라 **기존 무기의 상위 형태**로 취급한다.

### 7.2. 무기별 공격 방식

| 기본 무기 | 공격 메커니즘 | 강점 | 구현 우선순위 |
| --- | --- | --- | --- |
| **환도** | 주변 또는 전방 부채꼴 베기 | 근거리 범위 공격 | **1순위** |
| **각궁** | 가까운 적을 향한 자동 화살 발사 | 원거리 공격 | 2순위 |
| **편곤** | 플레이어 주변을 도는 타격체 | 접근 적 견제 | 3순위 |

### 7.3. 전설 진화

| 기본 무기 | 진화명 *(창작 명칭)* | 기존 메커니즘 유지 + 변화 | 개발 단계 |
| --- | --- | --- | --- |
| **환도** | **어명도(御命刀)** | 베기 피해·범위 증가 | **첫 구현 목표** |
| **각궁** | **천명궁(天命弓)** | 기본 화살 발사 로직을 활용해 3발 발사 | **추가 구현 후보 — 유지** |
| **편곤** | **귀살편곤(鬼殺鞭棍)** | 기존 회전 로직을 활용해 회전체 3개 | **추가 구현 후보 — 유지** |

> 전설 무기 이름은 역사적 실존 무기명이라는 주장이 아닌 **게임용 창작 명칭**이다.

### 7.4. 진화 조건 예시

```text
환도 Lv.1
  ↓ 같은 환도 중복 획득
환도 Lv.2
  ↓ 같은 환도 중복 획득
환도 Lv.3
  ↓ 같은 환도 추가 획득
어명도 (전설 진화)
```

이 조건은 **예시**이며 강화 최대 레벨과 진화 시점은 테스트 후 결정한다.

### 7.5. 구현상 주의점

- 진화는 가능하면 별도 공격 시스템 대신 **기존 무기 데이터의 피해·범위·발사 수 변경**으로 구현한다.
- 각궁 3발과 편곤 3개는 오브젝트를 여러 개 생성·관리해야 하므로 단순 스탯 변경보다 추가 작업이 있다.
- 무기별 공격 로직은 독립적으로 두고, 공통 인터페이스(공격 주기·피해·레벨·진화 상태)를 공유한다.
- 무기 교체 시 현재 투사체·회전체를 어떻게 처리할지 구현 규칙을 정해야 한다.

## 8. 가챠 게이지와 보상

### 8.1. 게이지 충전

1. 좀비 처치 시 에너지 구슬이 드롭된다.
2. 플레이어가 구슬을 직접 회수하면 게이지가 증가한다.
3. 게이지가 최대치가 되면 전투를 멈추고 가챠 화면을 연다.
4. 보상을 확정한 후 전투를 재개한다.
5. 다음 가챠부터는 **필요 게이지가 단계적으로 증가**한다.

**게이지 증가량 예시**

| 가챠 회차 | 필요 게이지 | 누적 요구량 |
| --- | ---: | ---: |
| 1회 | 5 | 5 |
| 2회 | 8 | 13 |
| 3회 | 12 | 25 |
| 4회 | 17 | 42 |
| 5회 | 23 | 65 |
| 6회 | 30 | 95 |

> 위 값은 **예시 수치**다. 실제 획득 속도는 적 생성량·구슬 드롭량·이동속도에 영향을 받으므로 플레이 테스트로 조정한다.

### 8.2. 가챠 보상 종류

| 종류 | 보상 예시 | 적용 방식 |
| --- | --- | --- |
| **즉시 회복** | 탕약 | HP를 즉시 회복 |
| **무기** | 환도·각궁·편곤 | 중복 시 강화, 다른 무기는 교체 선택 |
| **패시브** | 줄행랑·눈치 백 단 등 | 능력치 또는 행동 효과 변경 |
| **전설 진화** | 어명도 등 | 별도 보상 풀보다는 **무기 강화 조건의 결과**로 처리 |
| **꽝** *(후보)* | 창고 먼지 | 보상 없음 또는 소소한 효과; 실제 도입 여부 미정 |

### 8.3. 리롤과 위험도

- 가챠 결과가 마음에 들지 않으면 **제한된 횟수**만큼 리롤한다.
- 리롤을 할 때마다 **위험도**가 증가한다.
- 위험도는 적 이동속도 또는 적 생성량에 영향을 주는 방향으로 검토한다.
- **게이지 요구량 증가**는 모든 플레이에 적용되는 기본 규칙이다.
- **리롤 위험도 증가**는 플레이어가 선택한 추가 부담이다.
- 가챠 확률, 리롤 횟수, 위험도 증가량은 미확정이다.

### 8.4. 궁중 가챠 연출

**가챠 화면 콘셉트 후보: ‘내탕고 뒤지기’**

왕실 물품을 뒤져 무기와 탕약, 기묘한 패시브를 발견하는 연출. 내탕고는 조선 왕실의 재물 관리와 관련된 역사적 명칭이며, 게임 속 무기·패시브 가챠 기능은 창작 설정이다.

- 일반 보상: **평범한 물건**
- 희귀 보상: **진상품**
- 전설 진화 연출: **국보급** *(게임 내 유머 표현이며 실제 문화재 등급과 무관)*
- 꽝 연출 후보: **창고 먼지**

예시 문구: “전하, 지금은 국고를 걱정할 때가 아니옵니다.”

### 9.4. 패시브 밸런스 유의사항

- 회피 확률에는 상한을 둬 무한 회피를 방지한다.
- 피격 후 무적은 ‘자동 주기 무적’과 구별한다.
- 공격속도는 최소 쿨타임을 설정한다.
- 무기 개수 증가·연속 발사는 **모든 무기에 일괄 적용하지 않고**, 호환 가능한 무기부터 확장한다.
- 체력 회복은 최대 HP를 넘지 않도록 처리한다.

## 10. 좀비 적과 보스

### 10.1. 등장 순서

**좀비 백성 → 좀비 궁녀 → 좀비 내시 → 좀비 호위무사 → 왕의 동생(최종 보스)**

새 적이 등장한 이후에도 이전 적이 함께 출현해 압박을 높인다.

### 10.2. 적별 설계

| 적 | 기본 행동 | 특징·연출 | 개발 우선순위 |
| --- | --- | --- | --- |
| **좀비 백성** | 플레이어를 천천히 추적 | 기본형. “전하… 세금…” | 1 |
| **좀비 궁녀** | 여러 마리가 무리 지어 접근 | 쟁반·빨랫감 등 소품 활용 가능 | 2 |
| **좀비 내시** | 접근 후 짧은 돌진 | “저어어언하아아!” | 3 |
| **좀비 호위무사** | 느리지만 높은 HP·피해 | 좀비가 되어서도 궁궐을 지키려는 듯한 움직임 | 4 |
| **왕의 동생** | 일반 추적 + 돌진 + 범위 공격 | 왕위를 탐낸 반란 주도자이자 최종 보스 | 5 |

> 실제 개발에서는 궁녀의 ‘무리 행동’을 복잡한 군집 AI 대신 **가까운 위치에서 여러 마리 동시 생성**으로 표현할 수 있다. 호위무사는 기본 추적 AI를 재사용하고 스탯만 강화하는 방식으로 먼저 구현한다.

### 10.3. 최종 보스

- **정체:** 좀비가 된 왕의 동생.
- **동기:** 자신의 왕위 계승을 주장하며 반란을 꿈꿨다.
- **전투 목표:** 보스 HP를 0으로 만든다.
- **공격 패턴 초안:** 추적, 예고 후 돌진, 범위 공격.
- **대사 예시:** “왕위는… 내 것이야…”
- **개발 원칙:** 우선 추적·돌진 두 패턴으로 클리어 가능한 보스를 만들고, 범위 공격은 여유가 있을 때 추가한다.

## 11. 스테이지·난이도 설계

### 11.1. 기본 맵

- **맵 1개:** 폐허가 된 궁궐 마당을 중심으로 구성.
- 시야에 들어오는 적을 피하면서 이동하고 에너지 구슬을 회수한다.
- 복잡한 실내 탐색이나 다중 맵 이동은 초기 범위에서 제외한다.

### 11.2. 4분 진행 예시

| 시간 | 신규 등장 적 | 진행 의도 |
| --- | --- | --- |
| **0:00~0:45** | 좀비 백성 | 이동·자동 공격·구슬 회수 학습 |
| **0:45~1:30** | 좀비 궁녀 | 적 밀집 대응 |
| **1:30~2:15** | 좀비 내시 | 돌진 회피 학습 |
| **2:15~3:30** | 좀비 호위무사 | 강화된 적과 누적 압박 |
| **3:30 이후** | 왕의 동생 | 최종 보스 전투 |

위 시간은 **밸런스 검증 전 예시**이며, 실제 게임 길이는 3~5분 범위에서 조정한다.

### 11.3. 난이도 증가 요소

- 경과 시간에 따라 새로운 적 유형을 추가한다.
- 경과 시간에 따라 적 생성량 또는 스탯을 증가시킨다.
- 리롤 시 위험도 상승을 별도로 적용한다.
- 게이지 요구량도 증가하지만, **적 수가 늘면 구슬 획득량도 늘 수 있으므로** 가챠 간격은 실측으로 조정한다.

| **캐릭터 컨트롤러** | WASD 이동, 속도 적용, 피격·이동 상태 |
| **입력 처리** | 키보드 이동, 마우스 가챠 선택, 일시정지 |
| **게임 오브젝트** | 플레이어, 좀비, 무기 공격체, 에너지 구슬 |
| **충돌 판정** | 플레이어-좀비, 공격체-좀비, 플레이어-구슬 |
| **오브젝트 관리** | 적 생성·삭제, 구슬 생성·회수, 투사체 수명 |
| **상태 전환** | 타이틀 → 가챠 → 전투 → 결과 |
| **애니메이션** | 이동, 공격, 피격, 사망, 진화 |

### 13.2. 권장 데이터 구조 *(설계 예시)*

```text
Player
 ├─ character_id
 ├─ hp / max_hp / defense / move_speed
 ├─ equipped_weapon
 ├─ passive_effects
 └─ invincibility_timer

Weapon
 ├─ weapon_id / display_name
 ├─ level / evolved
 ├─ damage / cooldown / range
 └─ attack()  # 무기별 동작 구현

Enemy
 ├─ enemy_type / hp / speed / damage
 ├─ update() / attack() / take_damage()
 └─ drop_energy()

EnergyOrb
 ├─ position / value
 └─ collect()

GachaManager
 ├─ gauge / required_gauge / draw_count
 ├─ reroll_count / danger_level
 └─ draw_reward() / apply_reward()

GameState
 ├─ TITLE
 ├─ START_GACHA
 ├─ PLAYING
 ├─ REWARD_GACHA
 └─ RESULT
```

> 실제 클래스·파일 이름은 구현 과정에서 변경할 수 있다. 무기별 공격과 충돌 처리는 pico2d 기반의 게임 월드 구조에 맞춰 설계한다.

### 13.3. 구현상 주요 위험

1. **콘텐츠 수 증가:** 캐릭터 8종과 좀비 5종의 애니메이션 제작이 예상보다 오래 걸릴 수 있다.
2. **무기별 공격 차이:** 환도·각궁·편곤은 서로 다른 충돌 및 공격 로직이 필요하다.
3. **리롤 밸런스:** 위험도가 지나치게 커지면 운이 나쁜 플레이가 불가능해질 수 있다.
4. **무기 교체:** 강화된 무기를 교체할 때 불리함이 과도하지 않은지 확인해야 한다.
5. **가챠 빈도:** 게이지 요구량과 실제 구슬 수집 속도가 적절한지 테스트해야 한다.
6. **성능:** 적·투사체·구슬의 생성·삭제를 적절히 관리해야 한다.

## 14. 개발 범위와 우선순위

### 14.1. 최소 플레이 가능 버전(MVP)

- [ ] 증가하는 가챠 게이지

- [ ] 리롤과 위험도 증가
- [ ] 무기 중복 강화
- [ ] 환도 → 어명도 진화
- [ ] 제한 시간 및 게임오버·클리어 판정

### 14.2. 목표 완성 버전

- [ ] 플레이어 캐릭터 8종 *(공통 로직·이미지 제작 여건에 따라 조정)*
- [ ] 기본 무기 3종: 환도·각궁·편곤
- [ ] 좀비 4종: 백성·궁녀·내시·호위무사
- [ ] 최종 보스: 왕의 동생
- [ ] 사극식 아이템 이름·설명 및 대사
- [ ] 무기 교체·유지 선택
- [ ] 주요 패시브 4~6종
- [ ] 궁궐 맵 및 핵심 UI

### 14.3. 추가 구현 후보 — 반드시 보관

- [ ] **각궁 → 천명궁** 전설 진화 (3발 발사)
- [ ] **편곤 → 귀살편곤** 전설 진화 (회전체 3개)
- [ ] 연속 발사·공격체 수 증가 패시브

## 15. 4주 개발 일정

| 주차 | 핵심 목표 | 완료 기준 |
| --- | --- | --- |
| **1주 차** | 플레이어 이동, 기본 좀비 추적, 환도 자동 공격, 충돌 | **이동·전투·사망**까지 작동 |
| **2주 차** | 구슬 수집, 가챠 게이지, 보상 팝업, 리롤, 무기 강화 | **처치 → 수집 → 가챠 → 강화 → 전투 재개** 연결 |
| **3주 차** | 적 종류 확대, 무기 교체, 패시브, 보스, 환도 진화 | **처음부터 클리어/게임오버까지** 플레이 가능 |
| **4주 차** | 궁궐 아트, 캐릭터 추가, 이펙트, 사운드, 밸런스, 버그 수정 | 안정적인 시연 및 제출 가능 |

**일정 원칙:** 2주 차까지 핵심 반복 루프를 완성하고, 3주 차까지 게임의 시작과 끝을 연결한다. 남는 시간에만 콘텐츠를 확장한다.

- 리롤을 전혀 하지 않아도 클리어 가능성이 있는가?
- 리롤 위험도 증가가 눈에 띄지만 불합리하지는 않은가?
- 무기 교체와 중복 강화 사이에 실제 선택 고민이 생기는가?
- 각 무기가 서로 다른 상황에서 유용한가?
- 보스 패턴이 알아볼 수 있고 회피 가능한가?

### 16.3. 프로젝트 완료 정의
